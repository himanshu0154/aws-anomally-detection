# SkyGuard AI — working notes for agents

## Shape of the repo
- Two halves that must stay in sync: `api/main.py` (FastAPI, canonical JSON schema, in-process state) and `frontend/` (Next.js 15 App Router). `ml/detector.py` is the detector; models are packaged in `models/skyguard_detector_v2.joblib`.
- The canonical API schema is mirrored by hand in `frontend/src/types/skyguard.ts`; a field added in `_build_history_record()` is invisible to the UI until that file is updated too.
- `frontend/src/lib/anomaly.ts` owns labels, lifecycle helpers and history filtering, and `frontend/src/lib/api.ts` owns every network call. Components should not re-implement either.

## Commands and environment
- Frontend dev server is port **4028** (`npm run dev`); backend default is 8000. Pick another port when validating (e.g. `8010`) to avoid clashing with a running dev server.
- `npm run build` cannot catch type or lint errors: `frontend/next.config.mjs` sets `typescript.ignoreBuildErrors` and `eslint.ignoreDuringBuilds`. Always run `npm run type-check` (and `npm run lint`) separately.
- Prettier is not an invariant here: files fail `npx prettier --check` at HEAD (CRLF checkout, older formatting). Format only files you touched. `.prettierrc` uses `endOfLine: "auto"`, so inserting LF lines into a CRLF file trips `prettier/prettier`; `--write` on that file resolves it.
- `npm run build` overwrites the `.next` a running `next dev` serves. Afterwards the dev server still answers, but documents 404 `_next/static/chunks/main-app.js` and come back as **static, unhydrated HTML** — it looks fine (SSR text, CSS animations run) yet nothing is interactive: no polling, no event handlers, no splash timer. Restart `next dev` after every build.
- The desktop preview webview is not composited: `requestAnimationFrame` never fires there, so rAF-driven behaviour cannot be exercised and `rafAlive` probes come back false. Verify interactivity through the DOM and computed styles (and through pixel readback of a serialized SVG) rather than screenshots — screenshots can also lag live DOM edits.
- There is no JS test runner and no pytest suite. For backend behaviour, use a project-local venv plus `fastapi.testclient` (`python -m venv .venv && .venv/Scripts/python -m pip install -r requirements.txt httpx`) and drive the real app with real rows from `data/test_processed.csv`.
- A TestClient run starts the lifespan simulator; set `main._simulator_running = False` right after entering the client to make readings deterministic.

## Detection pipeline facts that are not obvious from reading it
- `detector.detect()` order matters: missing-value, `|ΔT| > 8`, and frozen-sensor (`std(6) < 0.05`) rules run *before* the residual z-score test, which runs before the Isolation Forest — so a rule always wins over a generic `ml_anomaly`.
- `_build_engineered_row()` recomputes features from the buffer on every reading, so changing buffer semantics changes the features the model sees.
- `docs/notes.txt` says NASA POWER `PS` is kPa, but the CSV column and `VALID_RANGES['PS']` (850–1100) are hPa. The old `/api/series` value `pressureScaled = PS/10` on a shared 0–100 axis rendered real 3–27 hPa swings as ~0.7% of chart height — the "frozen pressure line" bug. `/api/series` now also returns raw `pressure`, plotted on its own right-hand axis.
- Root-cause shares in `_compute_root_cause_probabilities()` are heuristic and `drift` has no signal at all (always baseline). Do not describe them as calibrated probabilities.
- Gemini (`api/anomaly_classifier.py`) only classifies anomalies the IF already flagged, and is skipped when `GEMINI_API_KEY` is unset even though `GEMINI_ENABLED` exists.

## State and lifecycle invariants
- One record per processed reading in `history_events` (bounded deque, `HISTORY_MAX`); ids come from the monotonic `_history_counter`. Deriving ids from `len(history_events)` collides once the deque is full — do not reintroduce it.
- Current detection (`/api/live`) and event lifecycle (`/api/history`) are separate concepts: a normal reading must never rewrite an older anomaly's status. Only `POST /api/history/{id}/resolve` moves `Active -> Resolved`, and `Resolved` is never `Normal`.
- The frontend keeps a confirmed-resolution override until a poll reports the stored `Resolved`, otherwise an in-flight poll can flip a checkbox back. Keep that merge in `DashboardDataProvider`.
- All backend state mutation happens under `_lock`; functions that were given `recent_readings` must not read `reading_buffer` again.

## Frontend conventions
- Polling lives only in `DashboardDataProvider` (`frontend/src/hooks/useLiveDashboardData.tsx`); pages consume `useLiveDashboardData()`. Adding a `setInterval` in a page reintroduces duplicate timers per route.
- `AppShell` owns the splash, header, drawer and footer and never remounts on client navigation — that is what keeps the splash to once per page load. Adding splash logic to a route replays it on every navigation.
- `CloudBackdrop` (mounted once in `AppShell`) is the app's only WebGL layer and the only cloud shader: the splash deliberately has no canvas so startup and the dashboard are one sky, not two contexts. It sits at `-z-10` / `fixed`, which means `AppShell` must never paint a background — an in-flow ancestor background paints *over* a negative-z child and the clouds vanish.
- The backdrop is a **daylight sky**: `cloudColor="#ffffff"`, `skyTopColor="#4a86c8"` deepening at the top, `skyBottomColor="#b8d8f0"` at the horizon, under a `bg-background/35` scrim. Read off the shader's own buffer that lands at sky top ~(166,202,238), horizon ~(209,230,242), white clouds ~(251,250,247) against the deepest shadowed blue ~(143,181,219) — a ~108-level spread.
- Sky top colour and scrim trade off **directly**, and getting this wrong makes the layer invisible while it still runs perfectly on every route. The trap, hit twice: a sky that is a *tint of* `--background` `#f4f2e8` (`#dfe4d2 → #f4f2e8`) had the page background as its bottom stop, so a 70% scrim over it spanned ~238→247 against a 244 base (~2% contrast) — mounted everywhere, animated, flat. The sky must differ from the page background *and* the scrim must be loose enough to let that through. Deepening the sky or thinning the scrim also darkens the surface text sits on, so re-check contrast against the deepest blue afterwards: at `/35` the foreground token measures 5.4:1 there and 9.0:1 at the horizon.
- **Text on the sky uses `--foreground`, text on a card may use the muted/secondary tokens.** `--muted-foreground` `#7a7a5a` can never reach 4.5:1 against pure white (max ~4.46:1) so it cannot pass AA on *any* background; `--secondary-foreground` `#5c5c3d` reaches only 3.2:1 over the deepest blue. Every string sitting directly on the backdrop — page ledes, breadcrumbs, section captions, the splash's descriptive text — is therefore `text-foreground` (or `text-foreground/90` on the splash, where its extra wash lightens things). When adding a panel, ask which surface its text is on before choosing a token.
- **There is no station code.** The dataset carries no station column, so `STATION_ID` in `api/main.py` is deliberately `""` and nothing in the UI prints it: the header chip, the drawer's Station row, the footer line, the chart caption, the history table caption, the splash status line and the page lede all dropped it, and the board's first row labels itself `STATION` rather than naming an id. The `station_id` key stays in the payloads (and in `types/skyguard.ts`) so the response shape is unchanged — if you display it again it will render as an empty string, so don't.
- The split-flap station strip that used to sit under the header on every route has been **removed** (`StationStatusBoard` is deleted, along with its screen-reader paragraph). Its facts still reach the user through the header's online indicator, `AnomalyAlertCard` and the dashboard's counts — do not re-add a second surface for them. `components/ui/text-flipping-board.tsx` is now unused by the app and kept only as a reusable primitive: to use it again, size it with `cols`/`rowCount` (props, not media queries) and remember its glyph size comes from container-query units and its keyframes from `src/styles/tailwind.css`.
- `hooks/useReducedMotion.ts` and `hooks/useMediaQuery.ts` are the shared readers for those two preferences; the shader, board and wordmark all consume them rather than calling `matchMedia` themselves.
- Every animated canvas uses `hooks/useVisibleAnimationFrame.ts` (synchronous first paint, loop only while visible, always the latest callback). Do not hand-roll `requestAnimationFrame` in a canvas component: rAF never fires in a document that is not composited, so a canvas that waits for one paints blank, and the first paint must not depend on the loop.
- `components/ui/canvas-text.tsx`: `backgroundClassName` is the **glyph fill**, not the surface behind it (the ported name misleads; the demo passes blue for both). It only reads at display size — the wave lines need strokes thick enough to cross — so put it on an emphasised phrase, never body copy.
- The shared loop's synchronous first paint happens on mount, which is *before* `canvas-text` knows its glyph box, so that first frame bails on a zero-sized rectangle and the canvas falls back to depending on rAF — the exact failure the hook exists to prevent. It therefore also exposes its draw step as a `useCallback` and re-invokes it from an effect on any input change, and the shader passes an indirection ref (`frameRef`) set up in an earlier effect on purpose. If you add a canvas component, make a paint happen on the inputs changing, not only on the next frame; verify by stubbing `window.requestAnimationFrame = () => 0`, blanking the canvas, then forcing a re-measure — ink after that proves the synchronous path.
- `cloud-shader` paints its first frame synchronously and only then starts the rAF loop, so the backdrop is never blank in a document that is not being composited, and it stops the loop on `visibilitychange`. It also tunes itself: if 90 measured frames average worse than 33ms it steps down (fewer cloud layers → half resolution → ~15fps), never back up, logging `[CloudShader] frames averaging …` to the console — so a sudden quality drop in that log means the *machine* is struggling, not the config. Under reduced motion it draws only when something changed, so a static sky costs nothing. Props are read through `paramsRef` inside the loop; adding a prop that the effect closes over trips `react-hooks/exhaustive-deps` and would re-create the GL context.
- The Aceternity-style pieces under `src/components/ui/` (`cloud-shader`, `text-flipping-board`, `text-hover-effect`, `canvas-text`, `squiggly-text`) were ported to this stack: no `motion/react`, no Tailwind v4-only utilities, no new packages. Their keyframes (`flap*`, `wordmarkDraw`) live in `src/styles/tailwind.css` under `@layer components`; delete them and the animations silently do nothing.
- `squiggly-text` swaps an SVG displacement filter straight to the node rather than through state (a swap every `stepDuration` would re-render `children` ~8×/s for a purely visual change), and it widens the filter region to `-25%/150%` because the default region clips displaced glyph edges, which reads as truncated text rather than wobble. The effect deforms glyphs, so it belongs on a short label — it is wired to the "Anomaly Detected" label, which exists only while an anomaly is live, so the wobble *is* the urgency signal and the calm state stays still. Never put it on a reading or body copy.
- `useReducedMotion` starts `false` and settles in an effect, deliberately, so server and first client render agree — which means any behaviour keyed off it must *clear* an already-applied effect, not merely avoid applying one. `squiggly-text` does; a reduced-motion reader may see one displaced frame before the clear lands. When verifying that branch remember the environment cannot set the OS preference: `window.matchMedia` returns a fresh `MediaQueryList` per call here, so the hook's own instance cannot be reached and patched. Force the flag in the component, watch the effect disappear, then revert (Fast Refresh remounts it) — and confirm the revert landed by grepping the served dev chunk (`.next/static/chunks/app/page.js`) for the expression.
- Those components must not hardcode SVG ids: two instances on one page then share a mask/gradient and only the first lights up. Use `useId()`.
- Theme colours are `rgb(var(--x-rgb) / <alpha-value>)` in `tailwind.config.js` with triplets in `styles/tailwind.css`. With a plain `var(--x)` value Tailwind emits **no rule at all** for `bg-card/60` — silently, no warning — so every translucent surface was fully transparent until this was fixed. Keep both forms (hex for `var(--x)` consumers, triplet for utilities), and use multiples of 5: an off-scale modifier like `/68` is dropped even when the colour is alpha-capable.
- `src/lib/utils.ts` exports a dependency-free `cn` that only joins classes — it does not merge conflicting utilities the way tailwind-merge does. Stylesheet order decides, so a shared component must not bake in padding/radius/shadow that a caller wants to override; leave surface styling to the caller (`text-flipping-board` relies on this). There is no `components.json` and Tailwind is 3.4.6, not v4 — shadcn/ui is *not* set up, so shadcn-shaped snippets need porting, not `npx shadcn add`.
- `text-flipping-board` animates only cells whose target character changed, and `cloud-shader` logs `[CloudShader] shader compile failed:` (with a WebGL-unavailable warning) when it bails to the static fallback — check the console before debugging a blank splash as CSS.
- Production backend URL comes from `NEXT_PUBLIC_API_BASE_URL`; never hardcode it. Backend CORS reads `ALLOWED_ORIGINS` (dev appends `*` when `ENVIRONMENT != production`).
